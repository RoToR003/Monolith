# Android: запис медіа та відомі проблеми

Оновлено 19.11.2026. Це публічна тестова база, не підтверджений щоденний клієнт.

## Фізичний OnePlus: звіти власника

OnePlus 15 / Android 17 / ColorOS 17 / Chrome 157; асистент не має доступу до пристрою чи акаунта.

- QR-вхід, надсилання повідомлення та збереження входу працюють.
- Попередній чекліст фото / встановлення PWA / запуск з іконки / збереження входу пройдено загальним підтвердженням власника; напис пункту встановлення окремо не зазначено.
- Вхід номером показує доставку коду через Telegram, але код не надходить. QR — робоча альтернатива, не виправлення доставки.
- **Голосові залишаються спотвореними:** сильні артефакти й ривки у вкладці Chrome та PWA, вбудований мікрофон. Те саме голосове звучить погано й в офіційному клієнті.

Після відеопатча `6581f71` власник повідомив, що попередні проблеми відтворення нового кружка/таймера виправлені й перемикання вже працює. Але перемикання обирає **телеоб’єктив**, дизайн кнопки не прийнятний, а прев’ю запису виглядає овальним. Очікувана версія того ретесту — `6581f71-44526088655.1`; власник не звіряв її номер окремо.

Номери, коди, сесії та приватний вміст не збирались. Повний Android-чекліст не прийнято.

## Другий відеопатч: основний модуль і кругле прев’ю

1. Напрямок `facingMode: environment` **не визначає об’єктив**. Тепер після дозволу камери читаються перелічені браузером пристрої та їхні facing capabilities / назви. Перевага віддається основній / primary / 1× / звичайній wide задній камері, а не telephoto / ultrawide / macro. Android-назва `camera2 0, facing back` — запасна евристика, не гарантія моделі телефона. За рівних підказок зберігається browser default-first порядок.
2. Вибраний модуль запитується через **точний deviceId**; повертання до фронтальної камери пам’ятає її фактичний ID. Якщо acquire-helper непомітно підставив інший пристрій, такий результат відхиляється й робиться спроба відновити попередню камеру. Ідентифікатори лишаються в оперативній пам’яті recorder, не надсилаються й не логуються.
3. Мікрофон, canvas-track, файл і таймлайн запису, як і раніше, не перезапускаються. Життєвий цикл захищений і під час очікування списку пристроїв.
4. Прев’ю має **один адаптивний діаметр для обох осей**, `aspect-ratio: 1` та не стискається flex-layout. Старі незалежні `max-width`/`max-height` могли перетворити квадрат на овал. Progress ring отримав узгоджений SVG viewBox і масштабується разом із прев’ю.
5. Замість великої контрастної кнопки з рамкою — компактна напівпрозора кнопка з іконкою камери, зоною натискання 44×44 px і доступним підписом «Змінити камеру».

**Не оголошувати основний об’єктив гарантовано вибраним на OnePlus до фізичного ретесту.** Web API не має універсального стандартного прапорця «основний 1× об’єктив», а назви й доступні фізичні модулі залежать від браузера/виробника. Якщо знов обирається не той модуль, потрібні лише назви камер зі звичайного списку налаштувань, не сирий дамп сховища або device IDs.

## Перший відеопатч — підтверджений власником прогрес

- Перед викликом відкладеного програвача оновлюється сам остаточний об’єкт повідомлення/документа, а не лише `data-mid`.
- Таймер і кільце відхиляють `NaN`, `Infinity`, від’ємні значення та використовують тривалість документа, поки metadata від браузера не готові.
- Додано перемикання джерела відео без перезапуску мікрофона/енкодера, із відновленням попередньої камери й звільненням запізнілих getUserMedia.

Ці виправлення зберігаються; новий патч не повинен повертати дефект щойно надісланого кружка.

## Голосові: проблема НЕ виправлена

Поганий звук в іншому клієнті означає, що це не лише локальне відтворення Monolith. Потрібно розрізнити захоплення мікрофона, кодування/контейнер і обробку файлу при відправленні.

У синтетичному desktop-прогоні PCM → WebCodecs Opus → наш OGG muxer → декодер Chromium сильне спотворення не повторилося. Додатково згенерований WAV пройшов getUserMedia → справжній AudioWorklet/AudioEncoder/OGG з обома waveform-аналізаторами без відтворення дефекту. Це **не мікрофон OnePlus і не доказ справності Android-тракту**. У другому відеопатчі аудіокод не змінювався.

Для наступного кроку допоможе короткий 5–10-секундний нейтральний запис у Monolith як оригінальний `.ogg`/`.opus` файл, не перезапис динаміка. За можливості — контрольний запис тих самих слів офіційним клієнтом. Надавати файл необов’язково; приватне листування та файли сесії не потрібні.

## Автоматичні перевірки

- Вибраний suite: **97 тестів у 12 файлах**, не повний upstream suite/typecheck.
- Перевірки вибору основного модуля, повернення точної фронтальної камери, відмови від непомітної підміни пристрою й teardown під час enumeration.
- Реальна ізольована Solid-панель/SCSS: емуляція торкання, рівні сторони прев’ю та кільця, досяжна 44px кнопка у шести viewport: 320×568, 390×844, 412×915, 844×390, 390×360, 360×260.

```bash
# Після setup, з Node 24 у PATH:
pnpm exec playwright install --with-deps chromium
node scripts/monolith-media-smoke.cjs
node scripts/monolith-recording-ui-smoke.mjs
```

Обидва скрипти ізольовані від Telegram bootstrap/акаунта. Перший перевіряє синтетичні кодеки/контейнери та fake front/rear; другий — справжній UI-компонент/SCSS з емуляцією touch. Звіти в `.cache/monolith-media-smoke/report.json` та `.cache/monolith-recording-ui-smoke/report.json`. Вони не входять у сайт і не замінюють фізичний ретест.

## Повторний ручний сценарій

1. Оновити вкладку або закрити/відкрити PWA, **не очищаючи дані й не виходячи з акаунта**. Звірити нову версію в `about.html`.
2. Почати новий кружок: оцінити круглу форму та кнопку в портреті; повернути телефон і перевірити, що прев’ю не перетворюється на овал.
3. Перемкнути на задню камеру: порівняти кут огляду зі звичайним 1× режимом системної камери, повернути фронтальну; надіслати й перевірити короткий результат.
4. Голосові й недоставку коду лишити відкритими незалежно від успішного відеоретесту.
