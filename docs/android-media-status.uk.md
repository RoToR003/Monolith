# Android: запис медіа та відомі проблеми

Оновлено 19.11.2026. Це публічна тестова база, не підтверджений щоденний клієнт.

## Звіт основного тестувальника

На OnePlus 15 / Android 17 / ColorOS 17 / Chrome 157 власник повідомив:

- QR-вхід, надсилання повідомлення та збереження входу працюють.
- Попередній чекліст фото / встановлення PWA / запуск з іконки / збереження входу пройдено; точний напис пункту встановлення окремо не зазначено.
- Вхід номером показує доставку коду через Telegram, але код не надходить. QR — робоча альтернатива, не виправлення доставки.
- Голосові, записані в Monolith вбудованим мікрофоном, мають сильні артефакти й ривки **як у вкладці Chrome, так і в PWA**. Те саме надіслане голосове звучить погано й в офіційному клієнті.
- Щойно надісланий кружок показує `NaN:NaN`, натискання не дає нормального відтворення до повторного відкриття клієнта. Старі кружки працювали й до цього; після повторного відкриття новий кружок теж відтворюється.
- Під час запису кружка немає перемикання фронтальної/основної камери.

Це результати власника фізичного пристрою, не віддалена перевірка асистентом. Номери, коди, сесії та приватний вміст не збирались. Версію початкової збірки тестувальник окремо не звіряв; очікувана — `b2dd003-44516934767.1`.

## Зміни для повторної перевірки кружків

1. Перед запуском відкладеного програвача щойно надісланого кружка тепер оновлюються **сам об’єкт повідомлення й документ**, а не лише `data-mid`. Раніше програвач міг залишатися прив’язаним до тимчасового повідомлення.
2. Таймер і кільце прогресу відхиляють `NaN`, `Infinity`, від’ємні значення та використовують тривалість документа, поки браузер не надав коректні metadata.
3. Додано кнопку «Змінити камеру» під час активного запису, якщо браузер перерахував більше однієї камери. Змінюється лише джерело відео; мікрофон, canvas-track, файл і таймлайн MediaRecorder залишаються тими самими. При невдачі робиться спроба відновити попередню камеру; при втраті камери запис призупиняється, а не надсилається автоматично. Задня камера не дзеркалиться у preview.
4. Закриття чату/зупинка під час перемикання звільняє й камеру, яка ще очікувала getUserMedia.

**Це виправлення коду, покриті регресійними тестами; фізичний OnePlus має повторно їх підтвердити.** Синтетичне перемикання двох джерел не є перевіркою реальних фронтальної й задньої камер.

## Голосові: проблема НЕ оголошена виправленою

Поганий звук в іншому клієнті означає, що це не лише локальне відтворення Monolith. Потрібно розрізнити захоплення мікрофона, кодування/контейнер і обробку файлу при відправленні.

У синтетичній настільній перевірці PCM → WebCodecs Opus → наш OGG muxer → декодер Chromium сильне спотворення не повторилося. Це **не перевірка мікрофона OnePlus і не доказ справності Android-тракту**. Аудіокодек, обробку мікрофона та дозволи навмання не змінювали.

Для подальшої діагностики бажаний короткий 5–10-секундний запис без особистих даних, створений у Monolith і наданий як оригінальний `.ogg`/`.opus` файл, не перезапис звуку динаміка. За можливості — окремий контрольний запис тих самих слів офіційним клієнтом. Надсилати файл необов’язково; приватне листування чи файли сесій не потрібні.

## Автоматичні перевірки

- Вибраний локальний suite: **78 тестів у 10 файлах**; не повний upstream suite.
- 26 нових перевірок: фінальна ідентичність повідомлення, безпечний таймер, контроль камери, безперервність мікрофона, відновлення й teardown; додатково 5 наявних перевірок завантаження object URL.
- Синтетичний браузерний тест без Telegram API та акаунта:

```bash
# Після setup, з Node 24 у PATH:
pnpm exec playwright install --with-deps chromium
node scripts/monolith-media-smoke.cjs
```

Тестує лише реальні кодеки/контейнери Chromium на штучних даних, підміну джерела камери та локальні helper-функції. Не доводить доставку/відтворення авторизованого повідомлення в реальному чаті. Звіт — `.cache/monolith-media-smoke/report.json`; у сайт він не включається.

## Повторний ручний сценарій

1. Оновити вкладку або закрити/відкрити PWA, **не очищаючи дані й не виходячи з акаунта**. Звірити поточну версію в `about.html`.
2. Записати 5–10 секунд кружка, під час запису перемкнути камеру й повернути назад. При помилці — записати повідомлення, не повторювати багато разів поспіль.
3. Надіслати в «Збережене» й **відразу, без перезаходу**, перевірити тривалість, рух, звук і повторне натискання.
4. Порівняти той самий кружок в офіційному клієнті та перевірити старий кружок на регресію.

Недоставку коду та пошкодження голосових не закривати лише через успішний QR-вхід чи проходження синтетичних тестів.
